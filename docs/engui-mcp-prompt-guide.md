# Engui MCP prompt guide

## Start here
1. Call engui_get_context to verify the fixed workspace and permissions. Use engui_list_models, engui_list_characters, engui_get_character and engui_list_presets to discover real IDs; never invent IDs or infer model health from configured=true.
2. Edit Character cards and default outfits with authoring tools when the owner requests lasting changes. Use a fresh editRevision/expectedRevision and UUID requestKey. Omitted fields are preserved; null removes a trait. Read again after revision conflicts.
3. Call engui_prepare_generation. It freezes exact prompts, references, settings and seeds (three variants by default) WITHOUT paid inference. Inspect snapshot.variants and warnings.
4. Call engui_start_generation only with conversation authorization for this paid generation, the exact planId/planDigest and a UUID requestKey. Retry the SAME operation with the SAME key and payload. Poll engui_get_batch using pollAfterSeconds; never blindly resubmit uncertain work.
5. Review previews with engui_get_image; download full original files with engui_download_artifact. Completed originals are preserved to Draft. Record an approved reference only after the owner selects it.

## Owner-controlled model availability
Only the owner decides which models are enabled for MCP generation. Read engui_list_models: enabledByOwner is explicit operator approval; configured means local endpoint/transport settings exist; available requires both. availabilityReason explains rejection. health=null means no live provider-health probe, not a healthy/unhealthy verdict. No automatic enablement or paid health tests. Zero warm workers and provider queue delays do not change owner approval.
Preparation, paid start and queued dispatch reject disabled models (MODEL_UNAVAILABLE). Already accepted work, historical plans/results and cancellation remain accessible. Ask the owner if another model is needed; do not bypass this policy through another tool.

## Vibe management and generation (MCP 2.6)
A Vibe may carry preferred=true in engui_list_vibes, engui_get_vibe and engui_list_presets(kind=vibes). This is an explicit owner recommendation for this workspace, not automatic prompt composition. No marker is returned for other Vibes/workspaces or trashed/missing presets. Always pass vibeId explicitly to apply it. No LoRA recommendations are inferred.
Vibes are shared workspace style/mood presets, NOT LoRAs, image references or Character identities. These tools edit the same records as the Vibes UI; no separate MCP library. Their baseDescription is text prepended to the positive prompt. compatibleSceneTypes and tags are advisory metadata, not automatic model/mode restrictions or model parameters.
1. Discover engui_list_vibes({query:"cinematic",status:"active",limit:20}) and follow nextCursor. engui_list_presets({kind:"vibes"}) remains compatible for active summaries. engui_get_vibe({vibeId:"REAL_ID"}) reads full fields and editRevision, including trash. No foreign-workspace access.
2. With curate scope, engui_create_vibe({name:"Warm film",baseDescription:"Warm cinematic lighting, subtle film grain.",tags:["cinematic"],compatibleSceneTypes:["portrait"],requestKey:"NEW_UUID"}) returns id and editRevision. Descriptions should contain reusable style/mood, not copied Character identity or scene action. No extraction model or paid generation is called by CRUD.
3. engui_update_vibe({vibeId:"REAL_ID",expectedRevision:"CURRENT_EDIT_REVISION",changes:{baseDescription:"Cool blue cinematic lighting."},requestKey:"NEW_UUID"}) is a partial update. Omitted fields are retained; [] explicitly clears tags/compatibleSceneTypes. Tags are trimmed/lowercased/deduplicated like UI. Empty name/description and unknown fields fail. REVISION_CONFLICT means read again and reconcile; never silently overwrite a newer UI/agent edit.
4. engui_delete_vibe({vibeId:"REAL_ID",expectedRevision:"CURRENT_EDIT_REVISION",requestKey:"NEW_UUID"}) moves the preset to trash, not permanent deletion. Read engui_list_vibes({status:"trash"}) and engui_restore_vibe with its fresh revision to restore. No cascade into saved scenes, plans or Jobs. All mutations require curate, not generate; same requestKey/payload replays the original response without duplicating/reapplying. A replay can be historical: use get_vibe for current state. Different intent/payload needs a new UUID.
5. To use a Vibe, pass vibeId:"REAL_ACTIVE_ID" in engui_prepare_generation with the usual model/mode/prompt/references/settings. This works with every owner-enabled MCP image model and supported mode; check available=true before preparing. OMIT vibeId for none. Do NOT manually prepend the same description: it is applied exactly once before wildcards, seeded choices and Character tags. Check snapshot.vibe (frozen source), snapshot.stages.vibePrompt (template) and snapshot.variants[].prompt (actual provider text).
6. Edits to the used Vibe name/description or trash/removal invalidate an unstarted plan with PLAN_STALE before provider submission. Unavailable IDs during preparation return VIBE_UNAVAILABLE. Prepare a NEW plan with a NEW requestKey; historical plans and outputs are never rewritten. Metadata-only tag/scene-type edits do not change a prepared prompt. Preparation, CRUD and restore never start paid inference; engui_start_generation still requires generation authorization.

## Uploading local images and image-to-image (MCP 2.4)
Use engui_create_upload for an image on the agent's machine. The server cannot read the agent's local path. Requires generate scope, but NEVER starts inference. Static PNG/JPEG/WebP up to25MiB and40megapixels only; other files (video, audio, archives, LoRA weights, SVG) are not supported by this image-reference uploader.
1. Read the actual file's MIME, byte count and lowercase SHA-256 locally. Call engui_create_upload({filename:"source.png",mimeType:"image/png",byteLength:EXACT_BYTES,sha256:"EXACT_SHA256",requestKey:"NEW_UUID"}). filename is a basename, not a path. Do not put base64, file contents, remote URLs or server paths into MCP arguments.
2. When status=pending, upload the raw file bytes to uploadUrl with an HTTP/file tool: curl --fail-with-body --request PUT --header 'Content-Type: image/png' --data-binary @/local/path/source.png "$UPLOAD_URL". Use the returned contentType for JPEG/WebP. No multipart wrapper or MCP authorization headers are needed. Do not follow redirects or print/publish the private URL. The link authorizes only this declared file and expires in at most10minutes; credential expiry/revocation and workspace removal invalidate it too.
3. PUT returns status=ready and source={kind:"gallery_asset",assetId:"REAL_ID"}. Use that exact source in references. engui_get_upload({uploadId:"RETURNED_ID"}) recovers status/source if the HTTP response was lost. Retrying the same PUT or create-upload with the same key/metadata never duplicates the import; create-upload renews a pending expired link. A different file requires a new requestKey. Trashed/deleted originals are never restored by retry.
4. Originals are stored byte-for-byte in this workspace's Draft Gallery as imported images, not as Jobs. They persist beyond link expiry and are available to previews, full downloads, Qwen references and MaskFlow image masks (mask alignment/grayscale rules still apply). Remove unwanted imports through Gallery or engui_delete_gallery_asset; do not delete a source while an unstarted/queued plan needs it. Changed/deleted references invalidate the frozen plan. If the agent cannot access/upload local bytes, explain that client limitation instead of inventing a server path or claiming success.
5. Discover engui_list_models and engui_list_presets({kind:"loras",modelId:"z-image"}). Prepare Z-Image with modelId:"z-image", mode:"image_to_image", references:[SOURCE], prompt:"...", width/height within advertised bounds, variantCount:1 for one image, optional seeds:[42], parameters:{steps:9,cfg:1,denoise:0.6}, optional loras:[{id:"REAL_LORA_ID",weight:0.8}], and a new UUID requestKey. negativePrompt is optional. No characterId, explicit task_type or image path is needed. Exactly one reference is required. denoise controls how much the source changes; select it deliberately. Width/height do not automatically come from the upload: choose them to match the intended aspect ratio. This is ordinary init-image i2i, not a ControlNet/OpenPose input.
6. Inspect the returned frozen prompts, reference SHA-256, settings and seeds. Only after authorization for this paid generation call engui_start_generation with the exact planId/planDigest and a new requestKey. Retry with that same start key. Poll engui_get_batch; read preview or full output using engui_get_image / engui_download_artifact. Engui encrypts the init image and sensitive prompt/LoRA fields before sending to the endpoint; ordinary numeric generation parameters follow the existing Z-Image contract. configured=true is configuration availability, not GPU capacity/health.

## Krea2 Turbo image-to-image (desktop and MCP)
Use modelId:"krea2-turbo", mode:"image_to_image", exactly one source in references, and parameters:{steps:8,cfg:1,denoise:0.35}. Sources may be uploaded images, Gallery assets or completed Job outputs. The same create-upload flow above applies. Width and height are required: 512..2048, multiples of64. The full source is resized to those dimensions (bicubic, no crop) before VAE encoding; choose a matching aspect ratio to avoid stretching. Discover compatible LoRAs with engui_list_presets({kind:"loras",modelId:"krea2-turbo"}); up to8 are supported with the same weights as text-to-image.
Denoise ranges0..1: lower values preserve more structure;1 allows full regeneration. Even0 performs a lossy VAE encode/decode and does NOT promise pixel identity. This is ordinary latent i2i, not semantic instruction editing, MaskFlow or ControlNet. No mask or second reference. negativePrompt is optional; with CFG1 it has no guidance effect. Prepare/review/start authorization, immutable reference hashes and encryption are unchanged. Text-to-image still accepts no references and no denoise parameter. The mobile UI has no new Krea2 mode switch in this release.

## Gallery curation and Draft promotion (MCP 2.7)
Gallery asset IDs, Job IDs, output IDs and batch IDs are different. Always use full returned IDs, never prefixes. common is the UI Added section; draft is Draft. A bucket is not a generation phase; status active/trash is separate.
- engui_search_gallery accepts optional bucket (draft/common/upscale) and status (active by default, or trash). Results include assetId/id, bucket, status, editRevision, SHA-256 and a reusable source. engui_get_gallery_asset({assetId:"FULL_ASSET_ID"}) reads current metadata including trash, without loading pixels.
- engui_save_output({source:{kind:"gallery_asset",assetId:"FULL_ASSET_ID"},bucket:"common",requestKey:"NEW_UUID"}) promotes a Draft to Added IN PLACE. The SAME assetId, bytes, hashes, tags, favorites, timestamps of original addition and generation provenance are retained; no second Gallery copy. The response reports action:"moved", previousBucket:"draft", bucket:"common", status:"active" and new editRevision. Saving a Job output that is already preserved reuses/moves that asset too. New unsaved originals return action:"created"; already in the requested bucket returns action:"unchanged". Explicit bucket:"draft" can move a saved result back.
- engui_get_batch variants expose gallery:{assetId,bucket,status} from current Gallery state, including trash; this is NOT part of the immutable generation plan. It changes after promotion/deletion/restoration while generation state and frozen provenance do not. Promotion cannot make late automatic preservation recreate a Draft.
- To discard an unwanted image, read engui_get_gallery_asset, then engui_delete_gallery_asset({assetId:"FULL_ASSET_ID",expectedRevision:"CURRENT_EDIT_REVISION",requestKey:"NEW_UUID"}). Requires curate scope. This moves only that Gallery record to Trash, never permanently erases the file, original Job, another Gallery copy, historical plans or references. It disappears from active search; previews/downloads and new generation via that Gallery source are unavailable. Do not trash a source needed by an unstarted/queued plan: validation will reject it before submission.
- To undo, search status:"trash" or read its known assetId, then engui_restore_gallery_asset with the fresh expectedRevision and a new requestKey. It returns to its previous bucket with the same ID. REVISION_CONFLICT means read again and reconcile; do not blindly overwrite a newer move or edit. Restoration does not regenerate or rewrite plans.
- Older versions may already have made a Draft/common duplicate. Moving into a conflicting section returns GALLERY_DUPLICATE with sourceAssetId, existingAssetId and target bucket/status, changing neither record. Inspect both; use the desired existing asset and explicitly trash the redundant one with its fresh revision. Do NOT merge arbitrary images by hash alone, silently delete either record, or invent a replacement ID.
- All writes are idempotent with the same requestKey/payload; a different intent needs a new key. Replaying a receipt does not move/restore/trash again and can return HISTORICAL state. Receipts created before2.7 can lack the new status/action fields. Read engui_get_gallery_asset for current status after a replay. No new generation, file copy or paid inference is needed for curation.

## Bulk deletion (MCP 2.8)
Use batch tools instead of one call per item when cleaning up many records. limits.maxDeleteBatchItems is100. IDs must be full and unique within the request; use explicit selected IDs, not a query or "delete all". Empty/oversized lists, duplicates and malformed arguments reject the whole request before any deletion.
- Jobs: engui_delete_jobs({jobIds:["FULL_JOB_ID_1","FULL_JOB_ID_2"],requestKey:"NEW_UUID"}). Requires cancel scope. Same rules as engui_delete_job: known-provider active Jobs must first be cancelled, unresolved dispatch/preservation blocks deletion. Missing or already-deleted Jobs return ok:true, alreadyAbsent:true without disclosing other workspaces. Preserved Gallery files, plans, batch history and start receipts remain. No provider requests or regeneration.
- Gallery: engui_search_gallery({bucket:"draft",limit:50}) returns assetId and editRevision for every item. Follow nextCursor for more; collect selected items and call engui_delete_gallery_assets({items:[{assetId:"FULL_ASSET_ID",expectedRevision:"EDIT_REVISION_FROM_SEARCH"}],requestKey:"NEW_UUID"}). No individual get_gallery_asset calls are needed first. Requires curate; moves images to Trash, never permanently erases files or removes Jobs. Revisions prevent trashing images changed since inspection. Do not trash references still needed by unstarted/queued plans. Existing engui_restore_gallery_asset restores an item with a fresh revision.
- The response has total, succeeded, failed and ordered results. Each result identifies jobId or assetId and has ok:true with deletion details, or ok:false with error.code/message/retryable. Missing Gallery items return NOT_FOUND; changed ones REVISION_CONFLICT; protected Jobs JOB_BUSY. Other valid items still finish. This is partial success, NOT an all-or-nothing transaction. alreadyAbsent/changed:false count as successful no-ops.
- One UUID requestKey covers the entire ordered payload. Retrying after a timeout/disconnect with the SAME key and EXACT payload resumes completed checkpoints without repeating successful work. Reusing the key with changed IDs, revisions or order fails IDEMPOTENCY_CONFLICT before further deletions. A completed reply, including per-item errors, is historical and replays unchanged: a busy Job that later finishes is NOT silently deleted on replay, and a restored Gallery image is NOT trashed again.
- To retry items reported as failed, inspect their current state/revisions and send only the still-wanted failures under a NEW requestKey. retryable describes the condition, not permission to change the old payload. Unexpected infrastructure failures may stop a partial batch; resume with its original key/payload to recover. Split more than100 items into explicit chunks with a different UUID for each chunk. Keep request payloads until outcomes are known.

## Downloading full original artifacts
engui_get_image returns a resized WebP preview, NOT the full artifact. Use engui_download_artifact with source={kind:"job_output",jobId:"REAL_JOB_ID",outputId:"output-1"} or source={kind:"gallery_asset",assetId:"REAL_ASSET_ID"}. Take the exact source/outputId from engui_get_batch variants; use the Gallery source after the Job is deleted.
The result contains downloadUrl, filename, mimeType, byteLength, sha256 and expiresAt. Download that URL with an HTTP/file tool (GET; no MCP headers required). Write the response bytes directly to disk and compare byte count/SHA-256. Do not use a webpage/text extractor or re-encode a preview. If your client cannot download files, give the owner the private temporary link and say that limitation explicitly; do not claim the file was saved.
Links expire after at most10minutes, are scoped to that one original, and stop working after credential expiry/revocation, workspace removal or source deletion/trash. Treat the URL as private bearer access, never publish it. Request another link if expired; never generate another image for a download. Downloads preserve exact original format, dimensions and metadata without resizing/recompression. Local image/video/audio originals are supported, including files larger than the25MiB image-reference limit; remote-only originals are unavailable and never arbitrarily fetched. No new Gallery copy or paid job is created.

## Batch status and polling
engui_get_batch is read-only and uses the latest locally stored Job status; it never polls the provider itself or submits/retries work. observedAt is the time of this read, NOT the timestamp of a fresh provider response. Supervisor polling can lag provider transitions.
- queued: local Engui dispatch queue; not yet sent.
- submitting: preparing/sending the provider request; execution not confirmed.
- provider_queued: provider queue (Job queued/in_queue); NOT running inference.
- running: Job processing/in_progress/running confirms execution.
- finalizing: inference finished; retrieving/recovering the output, not another generation.
- awaiting_status: missing/unknown Job state; neither execution nor failure is confirmed. Do not guess or resubmit.
- submission_unknown: acceptance uncertain; requires reconciliation, never blind retry. Remaining queued variants are blocked with blockedReason=SUBMISSION_UNKNOWN.
- cancel_requested: cancellation is requested, not confirmed. phase preserves the last known execution stage; keep polling. Terminal results can still succeed after a cancellation request.
- abandoned: stopped locally after uncertain submission with no provider ID; terminal locally, slot released, but provider outcome is UNKNOWN. This is not confirmed remote cancellation.
- succeeded / failed / cancelled: terminal variant outcomes. Batch completed means all succeeded; partial means some succeeded and the rest failed/cancelled; needs_attention means uncertain submission.
The batch state summarizes remaining work: attention first, then cancellation, running, finalizing, submitting, provider_queued, awaiting_status, queued, blocked. Always inspect variants and counts for mixed batches. Completed siblings do not make a queued batch running.
counts contains mutually exclusive per-state counts (camelCase names such as providerQueued and submissionUnknown); they sum to total. No invented queue position, ETA or inference percentage is supplied. lifecycleState is internal dispatch bookkeeping retained for diagnostics/compatibility: its running means accepted/in flight, NOT confirmed inference. Use state and phase instead. jobStatus exposes only the stored raw status, not provider secrets.
When isTerminal=false, wait pollAfterSeconds before polling again. When isTerminal=true, pollAfterSeconds=0 means STOP ordinary execution polling, not immediate retry. Gallery preservation is separate: succeeded can temporarily have preservationState pending/failed; inspect assetId/preservationState or use engui_save_output, never regenerate to obtain a gallery copy.

## Concurrency, cancellation and deletion
limits.activeBatches (default 2, configurable by the operator) is Engui's per-workspace concurrency guard for paid batch starts, NOT a Qwen/RunPod limit. Queued, executing and unresolved submissions count as active; terminal abandoned work does not. Never bypass the cap by creating duplicate plans/batches.
Use engui_cancel_batch for unwanted work. It fences unsent variants and requests cancellation when a provider ID is known. Settled submission_unknown without a provider ID is explicitly stopped locally as abandoned; locallyStoppedJobIds and providerOutcomeUnknown disclose that outcome. An active dispatch lease must settle before local abandonment/deletion. Old cancellation requests are reconciled too.
Use engui_delete_job(jobId, requestKey) to remove a terminal Job, or locally stop/remove a settled uncertain Job. Requires cancel scope. Read jobId from batch variants. Active known-provider jobs must be cancelled first; preservation of successful originals must finish before deletion. Gallery assets, immutable plans, variant tombstones and start receipts remain, so replaying an old start returns its old batch and never generates again. Deleting locally is NOT proof of remote cancellation; do not automatically regenerate uncertain paid work.

## Generation without a primary Character (MCP 2.0)
engui_prepare_generation does NOT accept characterId, characterVersionId or outfitId. Remove these fields from client calls; they are rejected, not ignored. No Character card is required, even in an empty workspace. Do not create a dummy Character or erase a real card to generate plain text.
Plain text without Character tags receives NO implicit identity or outfit. Framing defaults to custom (no prefix); framing, view and Vibe affect the text only when explicitly selected. Stored wildcards and seeded alternatives still expand. Inspect snapshot.variants[].prompt for the exact provider text.
Inline mode (one or more Character tags, including tags from a wildcard or Vibe): descriptions are inserted ONLY at tag locations. Tag every intended person; no primary Character is chosen from the first tag. Tags capture current identities and, with :withOutfit, current default clothing. New plans have snapshot.schemaVersion=2 and characterMode plain or inline.
Concept review is separate: engui_record_concept_review still requires its own characterId to explicitly associate an image with a Character. It never changes generation text. Generated assets retain trusted plan/variant provenance; imported assets still need snapshotPlanId referencing that asset. Review records capture their selected Character for freshness checks.
Historical plans and approved references remain readable and unchanged. Old plans retain their original frozen prompts and original Character freshness checks; newly prepared plans use only tags. Reconnect MCP to reload the changed input schema. This tool prepares ordinary image Jobs, not a saved Prompt/scene entity.

## MaskFlow regional editing (MCP only)
Use modelId qwen-image-edit-maskflow, mode masked_image_edit, exactly one source in references and a separate mask. Call engui_list_models first; configured is not a live health check. UI and ordinary qwen-image-edit are unchanged.
- mask={kind:"image",source:{kind:"gallery_asset",assetId:"REAL_MASK_ASSET_ID"}} accepts an owned opaque grayscale image with exactly the source dimensions. White edits; black preserves; soft gray is allowed. Colored, transparent, empty and misaligned masks fail. Source and mask must have normalized EXIF orientation.
- Or mask={kind:"rectangles",regions:[{x:0.25,y:0.25,width:0.5,height:0.5}]} selects the central rectangle. Coordinates are normalized 0..1 relative to the full original source, not a cropped preview. Up to32 rectangles are unioned; everything outside is black. This is explicit geometry, NOT automatic text-to-mask segmentation.
- Output dimensions256..2048, multiples64, at most1048576pixels. Both inputs receive the same resize; choose the source aspect ratio. Baseline settings50steps/guidance4. Uses latest general-scene MaskFlow SFT and official Soft-Poisson; no Lightning or distilled adapter is implicitly enabled. No user LoRAs/negativePrompt in this adapter.
- Preparation freezes snapshot.mask input, image hash/source hash and dimensions. Review mask geometry and the exact prompt before a paid start. Changed/deleted masks or source images invalidate the plan; never reuse a second reference as a mask. Reuse by preparing a NEW plan from snapshot.draft with a new requestKey; old plans are immutable.
- Prompt, source, mask and output use Engui secure transport. Weights and runtime are baked into the endpoint image; no network model-cache disk or startup weight download is used. Cold start still pulls the image if absent and loads weights into GPU memory; provider_queued is not running inference. Provider executionTime includes initialization and media I/O, not only inference. No automatic retry of uncertain submissions.

## Character syntax (positive prompt only)
- {character:UUID}: current Character identity, WITHOUT clothing text; this does not mean nude.
- {character:UUID:withOutfit}: current identity plus CURRENT DEFAULT outfit. Missing/unavailable default outfit is an error; select one in Characters/wardrobe or use identity-only.
- Discover UUIDs via engui_list_characters. Multiple characters and repeated tags are supported within the fixed workspace, up to 32 distinct characters. Repeated tags use the same frozen source per preparation.
- Example: {character:PRIMARY_UUID:withOutfit} faces {character:RIVAL_UUID}. A wide shot in a rainy courtyard.
- UUID placeholders in examples must be replaced with real IDs. Unknown, deleted, foreign or malformed Character references fail with INVALID_CHARACTER_REFERENCE; no plan is saved. Negative prompt tags are rejected explicitly.
- Tags use full current identity text, not automatic region-cropped identity classification. Choose framing/action deliberately. Appearance text is literal: its braces and dollar signs are not evaluated recursively.

## Wildcards and seeded alternatives
Call engui_list_wildcards (query/cursor/limit) for active keys and values in this workspace. This read does not create defaults or edit wildcards.
- {key} expands a stored wildcard. {key:variantText} selects a matching value; {key:0,2} selects zero-based alternatives. MCP does not offer a persistent sequential cursor.
- {red|blue} chooses one alternative deterministically per seed. Character tags inside alternatives are protected before selection and inserted afterwards.
- Vibe text and wildcard expansion happen before seeded choices; all referenced Character tags in the expanded template must be valid, including alternative branches.
- Unknown ordinary wildcard keys remain literal text for compatibility: inspect the exact prepared prompts. Do not invent keys.

## Provenance, errors and reuse
The original source is snapshot.draft.prompt. snapshot.stages.expandedPrompt is the expanded TEMPLATE and can still contain tags. Actual provider prompts are snapshot.variants[].prompt.
Character substitutions are recorded separately in snapshot.characterReferences, snapshot.stages.characterReferences and each variant.characterReferences, including token, Character version, optional outfit revision and resolved text. wildcardReplacements is ONLY the ordinary wildcard log; an empty list does not mean Character resolution failed.
Plans are immutable. Edited/deleted referenced characters or changed default outfits invalidate an unstarted plan with PLAN_STALE; prepare again using a NEW requestKey. Historical plans and already-generated images are never rewritten. Legacy unresolved-tag plans must be prepared again. Do not start a plan containing an unintended literal tag.
This syntax works in MCP and Create Image/Create Video. Prompts/Prompt Constructor has no tag expansion; its existing Characters workflow remains separate. MCP currently exposes image generation, not Create Video's full API.
